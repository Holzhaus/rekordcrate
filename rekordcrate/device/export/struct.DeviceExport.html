Struct DeviceExport

pub struct DeviceExport { /* private fields */ }
Expand description

A handle to a Rekordbox device export: PDB database, setting files, directory structure.

open loads an existing export into memory, create starts an empty one. Either way every change stays in memory until save; dropping the handle without saving leaves the disk as it was.

pub fn create(device_root: impl AsRef<Path>) -> Result<Self>

Start a new, empty device export rooted at device_root.

The first save creates the PIONEER, PIONEER/USBANLZ, and Contents directories, the PDB database, and the default setting files — replacing the database and setting files of an export already at device_root.

Source

pub fn open(device_root: impl AsRef<Path>) -> Result<Self>

Open an existing device export at the given path, loading its databases into memory.

Scans the tables for their highest ids, so rows added later get ids that do not conflict, and for the names already present, so they are reused rather than duplicated. Tags are recovered from exportExt.pdb the same way; if that file is absent it is created on the first tag call, as in create.

Source

pub fn save(&mut self) -> Result<()>

Write the export to disk.

Every file is written to a temporary sibling and renamed into place, and export.pdb goes last, so an interrupted save leaves the previous export.pdb in place rather than a half-written one. The handle stays usable: keep adding and save again, or retry a failed save.

pub fn add_track(&mut self, track: &Track) -> Result<AddTrackOutcome>

Add a track to the export.

Resolves (creating where needed) the Artist, Album, Genre, Key, Label, and Artwork rows, then inserts a Track row pointing at them by ID.

Idempotent on non-empty file_path: if a track with that path was already added (this session or read back by open), the existing TrackId is returned and no new row is inserted. Tracks with an empty file_path are always inserted. Use AddTrackOutcome::is_new to tell the cases apart.

§Errors

If any of the track’s strings cannot be encoded, or a row is too large for a page. The track row itself is encoded and measured before any id is allocated or row inserted, so a bad one leaves the export untouched.

pub fn create_tag_category(&mut self, name: &str) -> Result<TagCategoryId>

Create a top-level tag category (e.g. “Genre”, “My Tags”) in exportExt.pdb and return its id. Leaf tags are grouped under a category via add_tags_to_track. The ext PDB is created lazily on first use, and written by save.

§Errors

Error::TagNameTooLong if name does not fit in a tag row.

Source

pub fn add_tags_to_track( &mut self, track_id: TrackId, category: TagCategoryId, tags: &[impl AsRef<str>], ) -> Result<()>

Tag track_id with tags under category in exportExt.pdb.

Empty labels are skipped. A label that already exists under the category reuses its tag instead of creating another, and a tag the track already carries is not linked again, so repeating a label (in this call, an earlier one, or before open) changes nothing.

§Errors

Error::UnknownForeignKey if track_id isn’t an existing track or category isn’t an existing category. Error::TagNameTooLong if a label does not fit in a tag row; the labels before it stay added.

Source

pub fn import_artwork(&mut self, source: impl AsRef<Path>) -> Result<String>

Import a host-side image as track artwork and return the device path to put in Track::artwork_path.

The image is decoded and resized right away into the 80×80 thumbnail and the 240×240 medium Rekordbox uses; both are written as JPEG under PIONEER/Artwork/ by the next save. Importing the same source again returns the same path, so tracks sharing a cover share one artwork.

§Errors

Error::ArtworkError if the image cannot be read, decoded, or encoded.
